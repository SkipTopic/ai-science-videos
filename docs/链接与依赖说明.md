# 链接与依赖说明

这份文档回答三个问题：**这个仓库里有什么"链接"？跑起来依赖什么？缺的东西去哪补？**

---

## 1. 本仓库内：没有任何目录联接（junction / symlink）

复制时用的是 `cp -a`（逐字节实体复制），所以：

- 所有目录都是真实目录，克隆到 Windows / macOS / Linux 都不会断链。
- 所有文件都是真实文件，没有软链接、没有快捷方式、没有 git submodule。
- 唯一"像链接"的东西是文档里的**相对路径引用**（README 里的 Markdown 链接），不影响运行。

## 2. 原工程里的目录联接（已在本副本中消除，但要知道它存在过）

原工程为了省空间，用了 **1 个 Windows 目录联接**：

| 原路径 | 指向 | 大小 | 本仓库怎么处理 |
|---|---|---|---|
| `工作区域文件夹/v2/remotion-studio-v2/node_modules` | `工作区域文件夹/remotion-studio/node_modules`（v1 的依赖） | 559 MB | v2 工程不收录；v3 用的是**独立完整副本**（782 MB），也不收录，`npm ci` 重建 |

相关的两个"隐形链接"（不是 junction，但同样是路径依赖）：

- `工作区域文件夹/voice/.venv` — Python 虚拟环境（21 MB），**没有**收进仓库；`tools/voice/*.py` 只需要系统 Python 3.12 + 几个包（见第 4 节）。
- `code/remotion-studio-v3/public/fonts` — 原工程里这个目录**本来就是空的**，靠脚本生成。仓库里放了 `README.md` 占位说明，避免 `git clone` 后目录消失。
- `code/remotion-studio-v3/public/audio/sfx` — 原工程也是空的，本仓库**已把 22 个合成好的 wav 一并放入**（11.6 MB），克隆即可渲染；重生成见 4.4。

> 纪律提醒（原作者定的）：**junction 不能用 `rm -rf` 删**，那会删穿到真实目录；要用 `fs.unlinkSync` 或 `rmdir`。这条对 clone 下来的仓库不适用（已无联接），但如果你把仓库再拷回本地做 junction，务必记住。

## 3. 脚本里的绝对路径（换机器必须改）

`code/remotion-studio-v3/scripts/*.sh` 顶部写死了原作者机器的根目录 `/c/Users/admin/Desktop/ai生成科普视频/RPG Maker科普/...`。逐个体检结果：

| 脚本 | 属于 | 在本仓库能直接跑吗 | 要改什么 |
|---|---|---|---|
| `render_v3_changed.sh` | v3 | ❌ | `ROOT` 改成本仓库 `code/` 的上一级；`PROJ="$ROOT/remotion-studio-v3"`；`BAK` 指向任意备份目录 |
| `concat_film_v3.sh` | v3 | ❌ | `ROOT`/`PROJ` 同上；脚本里的 `输出文件夹` 需自己建或改路径 |
| `render_all.sh` | v1 | ❌（v1 未收录） | 仅作历史留存，`PROJ` 指向 `remotion-studio` |
| `render_all_v2.sh` | v2 | ❌（v2 未收录） | 同上 |
| `concat_film.sh` / `concat_film_v2.sh` | v1 / v2 | ❌（未收录） | 同上 |
| `check_segments.sh` | v1 | ❌（未收录） | 同上 |

其余脚本（`contact_sheet.py`、`prepare_fonts.py`、`qa_stills.js`）用的是**相对脚本自身**的路径（`os.path.dirname(__file__)`），可以直接跑。

`tools/` 下的 Python 脚本同理，绝大多数用 `HERE = os.path.dirname(os.path.abspath(__file__))` 推路径，只有输出目录写死成原工程结构（例如 `make_film_sfx.py` 写到 `../remotion-studio/public/audio/sfx`），第一次跑之前看一眼文件头 5 行即可。


## 6. 大文件（成片）怎么放到 GitHub

三个全片都超过 **GitHub 单文件 100 MB 硬上限**，直接 `git push` 会被拒：

| 版本 | 文件 | 大小 |
|---|---|---|
| v1 | `20261021_RPGMaker_梦想与世界.mp4` | 190,627,739 B |
| v2 | `20261022_RPGMaker_梦想与世界_v2.mp4` | 518,006,804 B |
| v3 | `20261022_RPGMaker_梦想与世界_v3.mp4` | 516,351,141 B |

三种可行做法：

1. **GitHub Releases（推荐）**：仓库页右侧 `Releases → Draft a new release`，把 v3 成片当附件上传（单文件上限 2 GB），README 里加下载链接。仓库本身保持轻量。
2. **Git LFS**：`git lfs track "*.mp4"` 后提交，免费额度 1 GB 存储 / 1 GB 月流量，够放一版；克隆者需要装 Git LFS。
3. **外链**：传到 B 站 / 网盘，README 里只写链接，不把视频放进仓库。

目前仓库只放了 **24 MB 的序章样片**（`preview/`），足够让人点开就听到配音、看到画面风格。
