## 一次"瘦身"记录

2026-10-23 做过一次清理：**10.5 GB → 7.0 GB**，只删了三类东西——

1. 与交付件 **MD5 完全相同**的整片副本（v1/v2/v3 各一份，共 1.4 GB）；
2. 与 `out/chapters/` MD5 相同的分段副本；
3. 可自动重建的打包缓存（`node_modules/.cache`、`.npm-cache`，约 1.37 GB）。

**没删**：四份交付成片、三个工程的 `out/chapters`（30 个分段）、21 个快照 tar、Blender 渲染序列、`node_modules` 本体。逐项核对明细见 `docs/清理记录_20261023.md`。

> 有一个例外是故意保留的：`_备份/chapters_v2/RPGMaker00.mp4`（46 MB）是 v2 序章的旧渲染版，全库唯一、删了不可恢复，MD5 与 v2 工程里那份不同。

## 为什么仓库里不放这些 tar

- 21 个包内容高度重复（每个都是全量快照），解压后和 `code/` 里的 v3 源码 90% 重合；
- 单个 97 MB 已接近 GitHub 100 MB 单文件上限；
- 真正的"开发过程"价值在于**顺序与说明**，这部分已经整理成本表 + `docs/00_第*版进度_先读我.md`。

如果确实需要某个时点的完整工程，可以按上表在作者本地取对应 tar 解压（`tar -xzf rendersnap_xxx.tar.gz`）。
