# 视频制作环境搭建清单

> 场景：A 机写文案 → B 机渲染（Blender + MCP）
> 目标：模仿 B 站 / 抖音科普视频的质感
> 日期：2026-10-21

---

## 一、先想清楚：这类视频到底由什么构成

不要一上来就选软件。先看配比。

| 画面类型 | 占比 | 谁来做 |
|---|---:|---|
| 录屏 / 实拍 / 游戏画面 | ~60% | 直接采集，不需要"制作" |
| 文字卡 / 图表 / 2D 动效 | ~25% | **Remotion + Manim** |
| 3D 动画 | ~10% | Blender |
| 转场 / 特效 / 包装 | ~5% | Remotion 或 Resolve |

> **警告**：手上有 Blender 的人，最容易把 10% 的部分做成 60%，然后项目死在第一分钟。
> 这条片子里真正需要 3D 的：机械恐龙、MSX 机器、公司名划掉、梦日记的走廊。四处，够了。

---

## 二、技术选型：2D 为什么是 Remotion

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Remotion** | React/TS 写视频；AI 可直接生成代码；改文案→改代码→重渲染全自动；免费；可进 Git | 需要 Node 环境；复杂 3D 不行 | **主力** |
| **Manim** | 数学/图表/概念动画极强；3B1B 同款 | 不擅长排版和叙事；写起来慢 | **辅助，只做图表** |
| After Effects | 行业标准；模板多 | 收费；AI 无法直接改；工程文件不可 diff | 不推荐 |
| DaVinci Resolve | 免费；剪辑/调色/混音专业 | 不适合程序化生成 | **收尾必备** |
| Blender Grease Pencil | 已有 Blender 就能用 | 2D 动效效率远不如 Remotion | 不推荐做主力 |

**一句话**：Remotion 负责"生成画面"，Manim 负责"解释概念"，Resolve 负责"把它们剪成一条片子"。

## 三、两台机器的分工

### A 机（现在这台）· 文案与资产

| 项目 | 说明 |
|---|---|
| 文案 / 分镜 JSON | 已有，见 `02_文案\解说文案_全片_v1.md` |
| 素材采集 | 游戏录屏、老照片、界面截图 |
| 配音 | 建议真人录；若用 TTS，见第六节 |
| 字幕初稿 | 由旁白文本直接生成，无需识别 |

**这台机器不需要装视频软件。**它的产出是：`script.json` + `assets/` + `voice/`。

### B 机（渲染机）· 出片

| 项目 | 版本 | 用途 |
|---|---|---|
| Node.js | 20 LTS 或 22 | Remotion 运行时 |
| Remotion | 4.x | 2D 动效主力 |
| Python | 3.11+ | Manim / 脚本 |
| Manim Community | 0.18+ | 图表与概念动画 |
| ffmpeg | 6.x+ | 拼接、转码、抽帧 |
| Blender | 4.x（已有） | 3D |
| Blender MCP | 已有 | AI 控制 Blender |
| DaVinci Resolve | 19 免费版 | 最终剪辑、调色、混音 |
| Whisper | faster-whisper | 字幕时间轴对齐 |

### 硬盘与显卡

- Remotion 渲染吃 CPU，不吃显卡；4K 输出建议 16GB 内存起步
- Blender 的 Eevee 需要显卡；Cycles 可以 CPU
- 预留 **200GB** 给素材和中间帧（PNG 序列很占地方）

## 四、交接格式：分镜 JSON

这是整套流程的核心。**文案机和渲染机之间只传这个，不传 Word。**

### 文件结构

```
project/
├── script.json          ← 唯一真相
├── assets/              ← 录屏、图片、3D 模型
├── voice/               ← 配音，按场景切好
├── out/
│   ├── remotion/        ← Remotion 渲染的片段
│   ├── manim/           ← Manim 渲染的片段
│   └── blender/         ← Blender 渲染的片段
└── final.mp4
```

### script.json

```json
{
  "meta": {
    "title": "RPG Maker，梦想与世界",
    "fps": 30,
    "resolution": [1920, 1080],
    "duration": 965
  },
  "scenes": [
    {
      "id": "00-01",
      "t_start": 0,
      "t_end": 6,
      "kind": "capture",
      "asset": "assets/maze_walk.mp4",
      "narration": "我在迷宫走着。",
      "narration_in": 0.5,
      "subtitle": "我在迷宫走着",
      "sfx": ["footstep"],
      "transition": "cut",
      "note": "一镜到底，不要剪"
    },
    {
      "id": "00-02",
      "t_start": 6,
      "t_end": 10,
      "kind": "remotion",
      "component": "WhaleEnter",
      "props": { "expression": "normal" },
      "narration": "遇到了小鲸鱼。",
      "subtitle": "遇到了小鲸鱼",
      "sfx": ["dialog_pop"]
    },
    {
      "id": "01-05",
      "t_start": 240,
      "t_end": 260,
      "kind": "blender",
      "scene_file": "blender/mecha_dino.blend",
      "camera": "Cam_Wide",
      "narration": "他花了 100 万美元，在东京竖了一只巨型机械恐龙。",
      "subtitle": "100 万美元的机械恐龙"
    }
  ]
}
```

### kind 的六种取值

| kind | 谁渲染 | 必需字段 |
|---|---|---|
| `capture` | 直接裁剪已有视频 | `asset`, `in_point`, `out_point` |
| `remotion` | Remotion 组件 | `component`, `props` |
| `manim` | Manim 场景类 | `scene_class` |
| `blender` | Blender 无头渲染 | `scene_file`, `camera` |
| `image` | 静图 + Ken Burns | `asset` |
| `text` | 纯文字卡 | `text`, `style` |

### 渲染调度伪代码

```python
for s in script["scenes"]:
    if s["kind"] == "capture":
        ffmpeg_trim(s["asset"], s["t_start"], s["t_end"])
    elif s["kind"] == "remotion":
        render_remotion(s["component"], s["props"], s["id"])
    elif s["kind"] == "manim":
        manim_render(s["scene_class"], s["id"])
    elif s["kind"] == "blender":
        blender_headless(s["scene_file"], s["camera"], s["id"])
# 最后按 t_start 排序，ffmpeg concat
```

## 六、配音（这一条最影响成片质感）

何同学那种质感，**核心是真人配音**，不是画面。TTS 会立刻拉低档次。

三个方案：

| 方案 | 成本 | 效果 | 建议 |
|---|---|---|---|
| **真人录音** | 时间 | 最好 | **首选**。手机 + 安静房间就够 |
| GPT-SoVITS（本地） | 显卡 + 训练时间 | 接近真人 | 想批量生产时用 |
| Edge-TTS / Azure | 免费 / 少量费用 | 有明显 AI 味 | 只用于草稿对时 |

**工作流建议**：先用 Edge-TTS 生成一版"占位音"，用来卡时间轴、对字幕。等画面全部定稿，再真人重录一遍替换。这样不会因为改文案反复重录。

## 七、字幕

不要用语音识别做中文字幕——你的旁白文本本来就是准的。

正确做法：
1. 用 TTS/真人音频跑 Whisper，拿到**每个字的起止时间**
2. 把时间戳对齐到你已有的旁白文本上（强制对齐）
3. 直接输出 SRT

工具：`faster-whisper` + `whisperx`（做 forced alignment）。

## 九、最小可行路径（如果你只想先跑通）

不要一次装全套。按这个顺序：

1. **先装 ffmpeg + DaVinci Resolve**，用手头的录屏和图片，剪一条 1 分钟的样片
   —— 验证"节奏"和"文案"对不对，这一步不需要任何动画
2. **再装 Remotion**，只做三样东西：文字卡、数字弹出、转场
   —— 这三样占全片 20%，但决定了"像不像科普视频"
3. **最后才碰 Manim 和 Blender**
   —— 它们是加分项，不是地基

> 大部分人死在第二步之前：一上来就搭 3D，结果一个月过去，片头还没做完。

## 十、Godot 能不能替代 Remotion？（2026-10-21 补充）

**结论：在这台无 GPU 的云服务器上不能；在本地有显卡的机器上可以，但只适合做一件事——做一个真的能玩的东西。**

### 为什么这台 ECS 上跑不了

Godot 4 的三个渲染后端都需要图形接口：

| 后端 | 需要 | 这台机器 |
|---|---|---|
| Forward+ | Vulkan | 无驱动 |
| Mobile | Vulkan | 无驱动 |
| Compatibility | OpenGL 3.3 / GLES 3.0 | 虚拟显示适配器只有 OpenGL 1.1 软件实现 |

Remotion 能跑，是因为它借 Chrome 的 **SwiftShader**（纯软件渲染）兜底。Godot 没有这层兜底。

装 Mesa3D 的 llvmpipe 理论上能强行跑，但 2 核 CPU 软件渲染 1080p，一帧要几秒，不可行。

### Godot 做视频的真实短板

| 维度 | Remotion | Godot |
|---|---|---|
| 文字排版 | HTML/CSS，天生擅长 | Control + Theme，笨重 |
| 字幕/图表 | 组件化，改起来快 | 要自己搭一套 |
| AI 生成 | TSX 是标准 React，训练数据海量 | .tscn 是私有格式，层级/资源引用/信号都很绕 |
| 确定性渲染 | 帧即函数，天生确定 | 需要 `--fixed-fps` 才稳 |
| 输出 | 直接 MP4 | AVI（MJPEG），文件巨大，要转码 |
| 音频同步 | `<Audio>` 组件精确到帧 | Movie Maker 能录，但调节麻烦 |

**最关键的一条是第三行。** 你让 AI 写一个 Remotion 组件，它写的是标准 React；你让 AI 写一个 Godot 场景，它要生成 .tscn 的节点树 + ext_resource 引用 + 信号连接，出错率高一个量级。

### Godot 在这条片子里唯一值得用的地方

**做一个真的能玩的小 demo，然后录屏。**

你的开场是"我在迷宫走着，遇到小鲸鱼"。这个场景有两种做法：

- Remotion 模拟一个 RPG 界面 —— 看起来像，但动起来假
- **Godot 真的做一个能走、能打、能被 999 伤害打死的 demo** —— 录下来就是真的

后者明显更好，而且这是你的主场。观众能看出来"这是真玩出来的"还是"这是做出来的"。

同样的逻辑适用于任何需要"游戏手感"的镜头。

### 推荐分工

```
Godot（本地，有显卡）
  └── 只做「可玩的游戏片段」→ 录屏 → MP4
        ↓
Blender（本地，有显卡）
  └── 只做 3D 镜头 → MP4
        ↓
Remotion（云服务器，无显卡也能跑）
  └── 全部 2D 信息动画 + 字幕 + 最终合成
        ↓
DaVinci Resolve
  └── 调色、混音、压片
```

**一句话：Godot 负责"真的"，Remotion 负责"讲的"，Blender 负责"看的"。**
