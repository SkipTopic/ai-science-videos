## 0. 三十秒了解这个项目

一部 19 分 25 秒的 B 站科普解说视频，叫《RPG Maker，梦想与世界》。

讲的是日本 ASCII 公司 1977 年成立，1988 年在杂志附录里塞了一个做 RPG 的小程序，这个程序后来变成 RPG Maker，长出了《梦日记》《Ib》《去月球》《OMORI》，最后公司没了，软件还在。

文案已经定稿。你要做的是**把它变成画面**。

## 1. 你的任务

```
输入：一份导演脚本（画面/旁白/音效三段式）
输出：一条 MP4
```

**第一版的硬要求：纯 2D。不要 3D。**

不要用 Blender，不要用任何 3D 渲染器，不要打开 Maya。

**"迷宫"这类需要空间感的场景，用 2D 模拟 3D。** 具体手法见第 4 节。

原因很简单：渲染机没有 GPU，2 核 4 线程，7.7 GB 内存。Blender 渲一帧 1080p 要几十秒到几分钟，一条 19 分钟的视频要跑几天。这条路走不通。

## 3. 十条铁律

1. **只做 2D。** 不碰 Blender，不碰 Maya，不碰任何 GPU 渲染。
2. **不改文案。** 旁白一个字都不要动。觉得有问题，报告，不要自己改。
3. **不编事实。** 文案里的每个数字、日期、人名，都能在 `01_资料库` 里追到来源。不确定的，标出来问。
4. **字体必须本地。** 放 `public/fonts/`，用 `staticFile()` 引用。不要用 `@remotion/google-fonts`，这台机器连不上 Google。
5. **不要用 CSS animation / transition。** Remotion 逐帧渲染，CSS 动画会丢帧。一律用 `useCurrentFrame()` + `interpolate()` / `spring()`。
6. **不要用 `Math.random()`。** 每帧结果不一样，画面会闪。要随机用 `random('固定种子')`。
7. **输出直接编码 h264。** 不要 `--image-format=png`，7574 帧会写满 18 GB 磁盘。
8. **并发设 1。** `--concurrency=1`。2 核开并发只会互相抢。
9. **分段渲染。** 每 30–60 秒一段，渲完检查，删中间文件，最后 ffmpeg concat。
10. **不装新软件。** 环境已经配好了。缺什么，报告，不要自己装。

## 4. 第一版只做 2D：模拟 3D 的五种手法

这是这份文档最重要的部分。

这部片子里，只有三处需要"空间感"：

- **第 00 章**：迷宫（俯视 → 拉远 → 露出编辑器）
- **第 02 章**：客厅（电视、主机、小孩）
- **第 03 章**：编辑器界面（本身是 2D，不需要模拟）

剩下全是文字卡、图表、网页截图、游戏录屏。

### 手法一：等距视角（isometric）—— 首选

把地面画成 2:1 的菱形网格，物体按等距投影摆放。

```
菱形宽 : 高 = 2 : 1
一个小人站在格子上，脚底对齐菱形的中心
```

**为什么首选**：它本来就是 2D 游戏的语言。RPG Maker 的玩家一看就懂，而且完全不需要透视计算。

**怎么实现**：在 Remotion 里用 SVG 或 div 画菱形，坐标按 `x = (col - row) * 32`、`y = (col + row) * 16` 排。

### 手法二：CSS 3D transform —— 用来做转场

```tsx
// 把一张平面的俯视地图，压成有透视的斜视角
<div style={{
  transform: `perspective(900px) rotateX(${interpolate(frame, [0, 60], [0, 55])}deg)`,
  transformStyle: 'preserve-3d',
}}>
```

**用途**：第 00 章结尾，镜头从平视的迷宫拉远、抬起来，露出整张地图。用 `rotateX` 从 0 到 55 度，就是这个效果。

**注意**：只在转场用，不要全程开着。真 3D 变换在软件渲染下很慢。

### 手法三：视差层（parallax）

把画面拆成 2–3 层，不同层用不同速度移动。

```tsx
const far  = interpolate(frame, [0, 300], [0, -40]);   // 背景，慢
const mid  = interpolate(frame, [0, 300], [0, -90]);   // 中景
const near = interpolate(frame, [0, 300], [0, -180]);  // 前景，快
```

**用途**：第 02 章客厅的推镜、第 01 章东京街景的横移。

**这是最便宜、最有效的"假 3D"**。观众感知到的是深度，不是透视。

### 手法四：手绘光影

不要试图做真实光照。

- 物体的暗面，直接用一块深色形状盖上去
- 地面上画一个椭圆当影子
- 光源方向全片统一（建议左上）

**RPG Maker 的老游戏就是这么做的**，观众不会觉得假，反而会觉得"对味"。

### 手法五：景深与空气感

远处的东西：降低对比度、加一点灰、缩小。

```
近景：饱和度高、边缘清晰
中景：正常
远景：饱和度 -20%、亮度 +10%、轻微模糊
```

比真做景深快一百倍，效果够用。

### 一句话总结

> **不要模拟"3D 长什么样"，要模拟"人怎么看空间"。**
> 等距网格 + 视差 + 手绘影子，这三样加起来，观众就信了。

## 5. 分阶段交付

不要一次做 19 分钟。

### 第一段：00 章（0:00–1:45，约 4 分钟工作量）

这是全片最重要的 105 秒。做完这一段的验收标准：

- [ ] 迷宫能"走"（角色一格一格移动）
- [ ] 小鲸鱼立绘出现、受伤 5、反击 999、Game Over
- [ ] 镜头拉远，露出编辑器
- [ ] 音画同步
- [ ] 1080p / 30fps / h264 输出成功

这一段跑通，后面全是重复劳动。**先别急着做第二段。**

### 第二段：03 章的门演示（7:50–10:30）

这一段是录屏，不是动画。需要：

- RPG Maker 2000（或 MZ）的真实操作录像
- 放门 → 新建事件 → 条件分支 → 开关 → 试玩
- **一镜到底，不要剪**

没有录屏素材，这一段做不了。**先确认素材有没有。**

### 第三段：其余章节

按时间顺序铺。文字卡、图表、网页截图、游戏画面。

### 最后：合成

ffmpeg concat + 音频对齐 + 字幕压制。

## 6. 技术规范

| 项目 | 规格 |
|---|---|
| 分辨率 | 1920 × 1080 |
| 帧率 | 30 fps |
| 编码 | h264，CRF 18 |
| 音频 | AAC 192kbps |
| 字体 | 思源黑体 / 思源宋体 / 霞鹜文楷，全部本地 |
| 输出目录 | `C:\Users\admin\Desktop\ai生成科普视频\输出文件夹` |
| 命名 | `YYYYMMDD_主题.mp4` |

### 渲染命令

```bash
npx remotion render Main "../../输出文件夹/20261021_rpgmaker.mp4" \
  --codec=h264 \
  --concurrency=1 \
  --crf=18
```

### 分段渲染

```bash
# 只渲 0–45 秒
npx remotion render Main out/seg01.mp4 --frames=0-1350 --concurrency=1
# 渲完检查，然后删掉中间产物
```

## 7. 已知的坑

| 坑 | 表现 | 解法 |
|---|---|---|
| **磁盘只剩 18.7 GB** | 渲到一半报错 | 分段渲，每段完事删中间文件 |
| **中文字体缺失** | 字幕变方块 | 字体放 `public/fonts/`，`@font-face` 本地引用 |
| **2 核 CPU** | 渲染慢，开并发更慢 | `--concurrency=1`，耐心等 |
| **Windows Server** | 某些工具装不上 | 不要装，用现有的 |
| **Blender 5.2 出不了 MP4** | 只能 PNG 序列 | **不用管，第一版不做 3D** |
| **文案里的时间码是粗排** | 配音后可能对不上 | 以实际配音为准，字幕跟着音频走 |
