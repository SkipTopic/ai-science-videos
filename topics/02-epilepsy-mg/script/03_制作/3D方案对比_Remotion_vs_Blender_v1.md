# 3D 方案对比：Remotion vs Blender（癫痫科普）

> 调研/实验日期：2026-10-23
> 项目环境：Remotion 4.0.537 + React 19；2 核 CPU、无可用 GPU；Blender 5.2.2 LTS（Cycles CPU）。
> 结论先行：**Remotion 能做出“3D 感”，也能接真 3D（Three.js），但它不是建模软件；Blender 是完整 3D 工具，但在本机渲染很贵。**
> 对这部片：**抽象分层图用 Remotion CSS 3D；真 3D 模型/电影感 hero shot 才上 Blender；两者可以混合。**

---

## 1. Remotion 到底能不能做 3D？

能，分三条路线：

| 路线 | 是什么 | 依赖 | 能做到 | 做不到 |
|---|---|---|---|---|
| **CSS 3D** | `perspective` + `transform-style: preserve-3d` + `rotateX/Y/Z`、`translateZ` | 无，Remotion 自带 | 透视、层叠、翻转、3D 卡片、3D 标题、分层示意图 | 真实几何体、灯光、材质、遮挡、景深 |
| **Three.js / React Three Fiber** | 通过 `@remotion/three` 的 `<ThreeCanvas>` 接 Three.js | 需安装 `three` + `@remotion/three`（本工程未装） | 真 WebGL 3D：GLB/GLTF 模型、相机、灯光、材质、粒子、着色器 | 建模、雕刻、UV、复杂仿真（要外部资产/工具） |
| **2.5D / 伪 3D** | 图片分层 + 视差 + 缩放/旋转 + 景深模糊 | 无 | 低成本“立体感”，适合氛围图、老照片、AI 图 | 真正的三维空间关系 |

本次实验走的是**第一条（CSS 3D）**，因为零依赖、可立即验证。

## 3. Blender 在本机的真实成本

| 项 | 数值 |
|---|---|
| 渲染器 | Cycles CPU（EEVEE / Workbench 会崩） |
| 720p / 8 采样 | 约 **16.8 秒/帧** |
| 1080p / 8 采样 | 约 **39 秒/帧** |
| 5 秒镜头（150 帧） | 720p 约 **42 分钟**；1080p 约 **97.5 分钟** |
| 10 秒镜头（300 帧） | 720p 约 **84 分钟**；1080p 约 **195 分钟** |

> 以上是纯渲染时间，不含建模、材质、灯光、动画、试错。Blender 的强项是“真实感/复杂场景”，弱项是“本机时间成本”。

## 4. 核心区别

| 维度 | Remotion CSS 3D | Remotion + Three.js | Blender |
|---|---|---|---|
| 本质 | DOM/CSS 透视 | 浏览器 WebGL 实时 3D | 完整 3D DCC + 离线渲染 |
| 建模 | 不能 | 不能（可导入 GLB/GLTF） | 能（建模/雕刻/UV/绑定） |
| 灯光/材质 | CSS 渐变、伪光 | 简单 PBR/灯光 | Cycles 路径追踪、复杂材质 |
| 复杂场景 | 低 | 中（受软件渲染限制） | 高 |
| 物理/仿真 | 无 | 需第三方库 | 内置流体/烟/布料/粒子等 |
| 渲染速度 | **快**（本次 ~0.5 秒/帧） | 未知，需实测；无 GPU 可能很慢 | **慢**（16.8–39 秒/帧） |
| 迭代 | 极快（Studio 热更新） | 快 | 慢（每改一次都要重渲） |
| 与字幕/2D/旁白整合 | **最好**（同一 React 树） | 好 | 需导出 PNG/MP4 再合成 |
| 数据驱动 | 强（props/JSON） | 强 | 弱（要写脚本/几何节点） |
| 医学影像感 | 只能“示意” | 取决于模型 | 最容易做“真实感”，但也最容易误导 |
| 最适合 | 抽象分层图、3D 标题、数据图 | 可旋转模型、神经元网络、粒子 | 真实感脑/颅骨、电影感 hero shot、复杂环境 |

## 5. 对科普视频的帮助

### 5.1 Remotion 3D 最适合的镜头

- **抽象机制**：电信号、神经元网络、突触、电场、波、分子、DNA、轨道。
- **分层/ exploded view**：大脑皮层 → 网络 → 异常同步 → 扩散（本次实验）。
- **3D 数据可视化**：3D 柱状图、时间轴、比例模型（发病率、治疗率）。
- **3D 标题/角标/转场**：比纯 2D 更有空间感，且和字幕同一条时间轴。
- **需要频繁改文案/数字的镜头**：React 组件 + JSON，改一个字不用重做模型。

### 5.2 Blender 最适合的镜头

- **真实感解剖**：半透明颅骨/大脑、病灶位置、电极/手术路径。
- **电影感 hero shot**：开头/结尾的“大脑亮起”大镜头，复杂灯光、景深、体积光。
- **复杂环境/历史场景**：如果以后做“医学史”插叙。
- **物理仿真**：粒子、流体、布料等 Remotion 不擅长的东西。

### 5.3 对这部癫痫片的建议

1. **主力用 Remotion CSS 3D**：把“大脑分层 → 异常同步 → 扩散”做成 3–5 秒的 3D 示意图，放在第 01 章或第 04 章；零依赖、可控、可改文案。
2. **真 3D 模型只在必要时上**：如果老板一定要“可旋转的大脑/神经元网络”，先在**独立 sandbox** 装 `three` + `@remotion/three`，跑 60 帧 1080p 基准；**不要装进癫痫工程的共享 node_modules**（junction 会污染 RPG Maker）。
3. **Blender 最多 1 个 hero shot**：例如“半透明大脑里，一处异常放电亮起并扩散”。720p/8 采样渲染 + lanczos 上采样 1080p；5 秒预算约 42 分钟。用 PNG 序列（带 alpha）交给 Remotion 合成字幕/标注，而不是在 Blender 里做字幕。
4. **混合管线**：Blender/Three.js 只负责“3D 素材”，Remotion 负责时间轴、字幕、2D 标注、音乐、QA。这样既保留 Blender 的质感，又不丢掉 Remotion 的可控性。
5. **医学表达**：所有 3D 脑图标“示意/不是真实医学影像”；不要用真实患者发作视频；不要做高频闪烁。

## 6. 风险与限制

- **CSS 3D 不是真 3D**：没有真实遮挡、灯光、材质；文字在透视里会变形，所以本次把标签移到右侧 2D 图例。适合“示意”，不适合“解剖”。
- **Three.js/WebGL 在本机未验证**：工程没装 `three`/`@remotion/three`；2 核无 GPU，headless Chrome 可能走 SwiftShader 软件渲染，复杂场景可能比 CSS 3D 慢很多。必须先做 60 帧基准。
- **Blender 的时间成本**：本机 Cycles CPU 16.8–39 秒/帧；5 秒镜头 42–97.5 分钟，且不包含建模/材质/试错。不要用 Blender 做“每章都有”的常规镜头。
- **资产与准确性**：真实感脑模型需要医学顾问审核；免费模型可能解剖不准确或有 license 问题。宁可做“风格化示意”，不要做“看起来像真的但错了”。
- **光敏性**：3D 发光/闪烁要克制，避免 3 Hz 以上高频闪烁；本片观众里可能有光敏性癫痫患者。

---

## 7. 一句话决策

- **要“讲清楚结构关系”** → Remotion CSS 3D（现在就能做，0.5 秒/帧）。
- **要“真 3D 模型/可旋转”** → Three.js + `@remotion/three`，先沙盒基准，再决定。
- **要“电影感真实脑”** → Blender 1 个 hero shot，720p 渲、1080p 用，预算 40 分钟+/5 秒。
- **要“快、可改、和字幕严丝合缝”** → Remotion 永远是主舞台，Blender/Three.js 只提供素材。
